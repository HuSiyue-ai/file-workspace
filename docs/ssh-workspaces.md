# 在本地文件树中浏览 SSH 工作区

此功能让电脑上的 file-workspace 通过一个已配置的 SSH 主机，浏览指定的服务器目录。项目菜单中会同时保留本地项目和 SSH 入口；切换后继续使用同一个分栏文件树、预览区和 Markdown 编辑器。

它复用 OpenSSH 的主机别名和认证配置，并按需建立独立的 SSH 通道，不接管桌面端已经建立的连接。不会挂载磁盘、同步整个文件夹或开放 HTTP 端口。

## 前提

- 本机能够通过 OpenSSH 主机别名进行非交互连接，主机密钥已经验证。
- 服务器已安装 file-workspace。基础浏览需要 **1.9.0 或更高版本**，新建文件与传输需要 **1.12.0**，可恢复删除需要 **1.13.0**。配置中使用明确的远程 Python 和 `server.py` 路径。PDF 需要远程 Python 环境中的可选 PDF 依赖。
- 指定目录属于当前账号的授权范围。Markdown 保存和新建文件夹还需要该目录的写权限。

## 配置入口

在本机源码目录创建 `.runtime/ssh-workspaces.json`，然后重新构建和安装插件。此文件和生成的插件配置不纳入 Git；不要在公开提交中填写个人主机、路径或凭据。

以下仅为示例，请替换为自己现有的主机别名和安装路径：

```json
[
  {
    "id": "lab-shared",
    "label": "lab · 共享目录",
    "host": "my-lab-alias",
    "root": "/srv/projects/my-project",
    "python": "/srv/projects/my-project/tools/file-workspace/.venv/bin/python",
    "server": "/srv/projects/my-project/tools/file-workspace/plugins/markdown-math-preview/server.py",
    "backupRoot": "/srv/projects/my-project/tools/file-workspace/.runtime/backups"
  }
]
```

入口最多 8 个；`id` 必须唯一。`host` 只能是已配置的主机别名，不能包含 SSH 参数。路径必须为明确的 POSIX 绝对路径；可选的 `backupRoot` 必须在 `root` 内。没有此配置时，插件继续作为本地查看器使用。

构建时会把配置复制到生成插件的 `ssh-workspaces.json`。后端进程读取的是这份插件内配置，改动后需要重新构建、安装并加载后台。

## 日常操作

1. 打开 file-workspace，展开右侧文件树。
2. 点击文件树顶部的项目下拉菜单，选择 SSH 入口。
3. 单击文件夹展开，双击文件夹进入，点击 ↑ 返回上级。共享根目录处不会再返回其父目录。
4. 单击文件，在当前页预览。Markdown 支持阅读、段落编辑、源码编辑和手动保存；图片使用原有缩放控件。
5. 从同一菜单选择本地项目即可返回。切换前仍会检查未保存修改。

远程文件的双击也在当前页预览；不把 Linux 路径交给本机外部应用。复制路径得到服务器路径，加入聊天的路径或引用会注明 SSH 主机。文件名大小写和不同主机的草稿分别保留。

## 保存与连接故障

- 文件读取、图片读取、保存和新建文件夹由远程后端执行，路径范围限制为配置的 `root`，包括对符号链接越界的检查。此检查不是操作系统级沙箱。
- Markdown 保存继续检查读取时的 SHA-256 版本，先备份原文件，再替换；冲突时保留编辑内容并拒绝覆盖。
- 连接失败时，切换前的文件树和预览仍保留。后台不循环重连；下一次手动操作可以建立新通道。
- **保存期间断线可能无法判断服务器是否已经完成写入。** 插件不会自动重发保存。保留或复制草稿，重新读取服务器文件确认后再决定是否保存。
- 连接要求 `BatchMode=yes` 和 `StrictHostKeyChecking=yes`；插件不弹出密码输入框，不自动接受未知主机密钥，也不读取或保存 SSH 私钥。

配置错误不影响本地文件访问。若菜单里没有 SSH 入口，检查配置并重新构建；若入口存在但无法连接，先在终端确认该别名可非交互连接，以及配置的远程 Python、后端和根目录仍然存在。

## 从本地对话点击服务器文件链接

从本地对话打开普通文件链接并交给 file-workspace 后，插件会检查宿主传入的文件路径：本机路径继续在本机读取；落在已配置 SSH 根目录内的 POSIX 路径则通过对应入口读取。首次读取成功后自动建立该页的 SSH 会话，后续图片、保存和目录操作沿用它。

原来的 `/mnt/.../file.md` 链接可以保留。前提是该文件类型由宿主交给 file-workspace：在原生“打开方式”菜单选择一次插件后，宿主可以按主机和扩展名记住选择。CSV 或其他类型若仍进入内置查看器，需要分别选择；插件不能在自己尚未运行时拦截原生链接。

预览成功会显示文件树，展开路径并选中当前文件；自动定位不会抢走编辑焦点。已有本地项目根目录覆盖文件时沿用它，否则从文件所在文件夹显示。本次链接匹配 SSH 根目录时，从共享根目录展开。快速切换文件或手动关闭文件树会取消过期的自动定位。

自动分流只使用宿主提供的首次文件路径，不依据任意工具参数猜测服务器，也不自动转换保存请求。路径先做 POSIX 规范化，再按目录边界匹配最长根目录；不同服务器存在同样的最长匹配时要求手动选择。实际文件访问仍由远端根目录检查约束。
